# 搜索筛选条件保留当前页计划

## 1. 概要
当前所有搜索/筛选条件（文本搜索、职位状态、是否为管理岗、优先级）在变更时都会将列表重置到第 1 页。用户期望变更筛选条件后严格保留在当前页码，即使当前页码没有数据也不自动回到有效页。

## 2. 现状分析
- `src/pages/JobList/index.tsx` 中：
  - 主搜索输入框回车时执行 `setSearchValue(searchInputValue)` 并 `setCurrentPage(1)`。
  - 交付经理/交付顾问输入框目前仅更新状态，未重置页码。
  - 职位状态、是否为管理岗、优先级三个 Select 的 `onChange` 在之前的修复中加入了 `setCurrentPage(1)`。
- 本次仅移除主动重置页码逻辑，不增加任何页码修正或自动跳转，用户接受当前页码无数据的场景。

## 3. 拟修改内容

### 3.1 `src/pages/JobList/index.tsx`
- 移除主动重置到第 1 页的逻辑：
  - 主搜索输入 `onPressEnter` 中删除 `setCurrentPage(1)`。
  - 职位状态 Select `onChange` 中删除 `setCurrentPage(1)`。
  - 是否为管理岗 Select `onChange` 中删除 `setCurrentPage(1)`。
  - 优先级 Select `onChange` 中删除 `setCurrentPage(1)`。
- 保持“清空”按钮现有的重置逻辑不变（清空筛选后回到第 1 页）。

### 3.2 其他文件
- 无需修改 `styles.css`、`mockData.ts`、`JobFormDrawer.tsx`。

## 4. 假设与决策
- “搜索筛选条件”泛指搜索输入框及第二行所有下拉筛选条件，统一行为为“保留当前页”。
- 不过滤后结果是否支撑当前页码，均不自动跳转，完全保留用户当前页码。
- 清空所有筛选时仍回到第 1 页，符合用户“重新开始浏览”的预期。

## 5. 验证步骤
1. 翻到第 3 页，在搜索框输入关键词并回车，列表保持在第 3 页（若第 3 页仍有结果）。
2. 翻到第 4 页，选择“优先级”为“一级”，无论过滤后是否有数据，页码都保持在第 4 页。
3. 选择极端筛选（结果极少），页码仍停留在当前页，允许当前页无数据。
4. 点击“清空”按钮，筛选条件清空并回到第 1 页。
5. 运行 `npx tsc --noEmit` 无类型错误。
