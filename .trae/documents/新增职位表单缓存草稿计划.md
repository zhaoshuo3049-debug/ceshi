# 新增职位表单缓存草稿计划

## 1. 概要
当前新增职位表单关闭（未保存）后会清空所有已填写内容。期望仅在“新增”模式下保留上次填写内容，关闭后再次打开新增表单时自动回填；编辑模式仍按原记录回填，不受影响。

## 2. 现状分析
- `JobFormDrawer.tsx` 内部使用 `Form.useForm()` 管理表单。
- `useEffect` 在 `visible` 变为 `true` 时调用 `form.resetFields()`，导致每次打开表单都会被清空。
- 新增模式下默认只写入 `jobStatus: '进行中'`，其余字段为空。
- 编辑模式通过 `initialData` 回填完整数据。
- 表单提交后由父组件 `index.tsx` 更新 `jobList`，抽屉本身不保留任何中间状态。

## 3. 拟修改内容

### 3.1 `src/pages/JobList/JobFormDrawer.tsx`
- 新增组件内部状态 `draftValues`，用于缓存新增模式下用户最近一次未保存的表单值。
  - 初始值为 `undefined`。
- 修改 `useEffect` 初始化逻辑：
  - 当 `visible` 为 `true` 时：
    - 若存在 `initialData`（编辑模式）：
      - 调用 `form.resetFields()`。
      - 按现有逻辑回填完整数据，并解析 `workLocation` 为 `province`/`city`。
    - 若不存在 `initialData`（新增模式）：
      - 若 `draftValues` 存在，则调用 `form.setFieldsValue(draftValues)`，并根据 `draftValues.province` 设置 `selectedProvince`。
      - 若 `draftValues` 不存在，调用 `form.resetFields()` 并设置默认值 `jobStatus: '进行中'`。
- 为 `Form` 添加 `onValuesChange`：
  - 仅在新增模式下（`!initialData`）将当前表单值缓存到 `draftValues`。
  - 编辑模式下不缓存，避免编辑内容污染新增草稿。
- 修改 `handleFinish`/提交成功逻辑：
  - 提交成功后清空 `draftValues`（`setDraftValues(undefined)`），确保保存后再次新增是全新表单。
- 关闭抽屉（取消）时不清除草稿，保留缓存供下次新增使用。

### 3.2 `src/pages/JobList/index.tsx`
- 无需新增状态或修改逻辑。
- 现有 `onClose` 中重置 `editingRecord` 的行为保持不变。
- 成功提交后父组件继续更新列表并关闭抽屉。

## 4. 假设与决策
- 草稿仅在“新增”模式下生效；编辑模式始终读取 `initialData`。
- 新增草稿在用户成功提交后清空，未保存关闭则保留。
- 工作地点缓存同样以 `province` 和 `city` 两个字段保存，再次打开时恢复省市联动状态。
- 使用 `Form` 的 `onValuesChange` 进行缓存，会包含所有当前可见字段，不会误缓存不在表单中的字段（如 `id`、`createTime`）。

## 5. 验证步骤
1. 点击“新增”按钮，填写部分字段后点击“取消”关闭。
2. 再次点击“新增”按钮，上次填写的内容（除职位状态外）应自动回填。
3. 点击某行“编辑”，编辑模式下表单应显示原记录数据，不受新增草稿影响。
4. 在新增模式下填写内容并点击“确定”保存，保存成功后再次点击“新增”，表单应为全新状态（仅职位状态默认“进行中”）。
5. 运行 `npx tsc --noEmit` 无类型错误。
