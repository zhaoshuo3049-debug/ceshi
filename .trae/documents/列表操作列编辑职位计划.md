# 列表操作列编辑职位计划

## 1. 概要
将职位列表「操作」列的“查看详情”按钮改为“编辑”按钮，点击后弹出抽屉表单，可修改当前职位信息并保存。

## 2. 现状分析
- 当前表格操作列使用 `EyeOutlined`，`Tooltip` 文案为“查看详情”，点击无响应。
- 抽屉组件 `JobFormDrawer.tsx` 目前仅支持新增职位，提交时固定生成新 `id`、`createTime`，并将 `isNew` 设为 `true`。
- 工作地点在数据中保存为字符串（如 `浙江省-杭州市、上...`、`北京-北京市`），表单内已拆分为“省份 + 城市”两级联动。
- 列表数据通过 `jobList` 状态管理，`setJobList` 可以完成新增/更新。

## 3. 拟修改内容

### 3.1 `src/pages/JobList/index.tsx`
- 导入 `EditOutlined`（替换 `EyeOutlined`）。
- 新增状态 `editingRecord: JobItem | undefined`，用于区分新增/编辑。
- 操作列渲染：
  - 图标改为 `EditOutlined`。
  - `Tooltip` 文案改为“编辑”。
  - 点击时 `setEditingRecord(record)` 并 `setDrawerVisible(true)`。
- 新增职位按钮点击时 `setEditingRecord(undefined)` 并 `setDrawerVisible(true)`。
- `JobFormDrawer` 调用：
  - 传入 `initialData={editingRecord}`。
  - `onSubmit` 逻辑改为：
    - 若 `editingRecord` 存在，使用原 `id`、`createTime`，仅更新其他字段，`isNew` 保持原值。
    - 若不存在，保持现有新增逻辑。
  - 保存成功后关闭抽屉、重置 `editingRecord`、回到第 1 页。

### 3.2 `src/pages/JobList/JobFormDrawer.tsx`
- 扩展 `JobFormDrawerProps`：
  - 新增可选属性 `initialData?: JobItem`。
- 根据 `initialData` 判断模式：
  - `initialData` 存在 → 抽屉标题为“编辑职位”。
  - 不存在 → 标题为“新增职位”。
- `useEffect` 初始化逻辑调整：
  - `form.resetFields()`。
  - 若 `initialData` 存在：
    - 将各字段通过 `form.setFieldsValue` 回填。
    - 解析 `workLocation`（按第一个 `-` 分割）得到 `province` 和 `city`。
    - `setSelectedProvince(province)`，并回填 `province`、`city`。
  - 若不存在，保持现有默认值。
- `handleFinish` 调整：
  - 提交对象 `id` 与 `createTime`：
    - 编辑模式：使用 `initialData.id`、`initialData.createTime`。
    - 新增模式：生成新 `id`、当前日期。
  - `isNew`：编辑模式保持 `initialData.isNew`；新增模式设为 `true`。
  - `workLocation` 仍拼接为 `${province}-${city}`。

### 3.3 `src/pages/JobList/styles.css`
- 本次无需新增样式，现有抽屉与表单样式可直接复用。

## 4. 假设与决策
- 工作地点字符串统一按第一个 `-` 拆分；左侧为省份，右侧为城市。若未来数据格式不固定，再调整解析逻辑。
- 编辑职位时“创建时间”不可修改，保持原值；“职位 JD”可修改。
- 编辑完成后回到第 1 页，与新增后行为一致，便于用户立即看到更新结果。
- 继续使用 `JobFormDrawer` 单一组件承载新增/编辑，减少重复表单代码。

## 5. 验证步骤
1. 列表每条数据操作列显示“编辑”图标。
2. 点击编辑图标弹出抽屉，表单自动回填当前行数据，工作地点正确拆分为省份和城市。
3. 修改字段后点击确定，列表对应行数据刷新，且创建时间/id 不变。
4. 点击“新增”按钮仍按原逻辑新增职位。
5. 运行 `npx tsc --noEmit` 无类型错误。
