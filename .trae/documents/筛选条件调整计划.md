# 筛选条件调整计划

## 1. 概要
将第二行筛选条件中的：
- “是否分配” 改为 “是否为管理岗”
- “是否concall” 改为 “优先级”

同时把这两个筛选条件真正接入列表过滤逻辑，并更新已选筛选标签、清空逻辑及清除按钮默认展示样式。

## 2. 现状分析
- `src/pages/JobList/index.tsx` 中已有状态 `isAssigned` 和 `isConcall`，但 `filteredData` 未使用它们，当前仅作为展示标签。
- 页面渲染了两个 Select：
  - “是否分配”：`className="filter-select is-assigned-select"`，选项 `yes/no` → 已分配/未分配。
  - “是否concall”：选项 `yes/no` → 是/否。
- `activeFilters` 会生成 `是否分配` 和 `是否concall` 标签。
- `styles.css` 通过 `.is-assigned-select` 让清除按钮默认显示。

## 3. 拟修改内容

### 3.1 `src/pages/JobList/index.tsx`
- 状态重命名与替换：
  - `isAssigned` / `setIsAssigned` → `managerFilter` / `setManagerFilter`（是否为管理岗）。
  - `isConcall` / `setIsConcall` → `priorityFilter` / `setPriorityFilter`（优先级）。
- `filteredData` 接入过滤逻辑：
  - 若 `managerFilter` 有值，过滤 `item.isManager`：
    - 当选择“是”，匹配 `item.isManager === '是' || item.isManager.startsWith('是')`。
    - 当选择“否”，匹配 `item.isManager === '否'`。
  - 若 `priorityFilter` 有值，精确匹配 `item.priority === priorityFilter`。
- 筛选 UI 调整：
  - 将“是否分配”标签改为“是否为管理岗”，Select 选项改为：
    - `<Option value="是">是</Option>`
    - `<Option value="否">否</Option>`
  - 将“是否concall”标签改为“优先级”，Select 选项改为：
    - `<Option value="一级">一级</Option>`
    - `<Option value="二级">二级</Option>`
    - `<Option value="三级">三级</Option>`
  - 将 `.is-assigned-select` 类名改为 `.manager-select`，保持清除按钮默认显示。
- `activeFilters` 更新：
  - `是否分配: ...` → `是否为管理岗: 是/否`
  - `是否concall: ...` → `优先级: 一级/二级/三级`
- 一键清空逻辑更新：重置 `managerFilter` 和 `priorityFilter`。

### 3.2 `src/pages/JobList/styles.css`
- 将 `.is-assigned-select.ant-select-allow-clear .ant-select-clear` 选择器改为 `.manager-select.ant-select-allow-clear .ant-select-clear`，使“是否为管理岗”的清除按钮默认显示。

## 4. 假设与决策
- “是否为管理岗”使用单选下拉，选项值为“是/否”，兼容数据中可能存在的“是（30）”格式。
- “优先级”使用单选下拉，选项值与数据一致：一级/二级/三级。
- 两个筛选条件从“仅展示标签”提升为“真正过滤列表”。
- 保持现有 Select 宽度 160px 不变。

## 5. 验证步骤
1. 页面第二行筛选条件显示“是否为管理岗”和“优先级”。
2. 选择“是否为管理岗”为“是”，列表只展示管理岗职位。
3. 选择“优先级”为“一级”，列表只展示优先级为一级的职位。
4. 已选筛选区域正确展示 `是否为管理岗: 是`、`优先级: 一级` 等标签，点击可移除。
5. 点击“清空”按钮，两个筛选条件均被重置。
6. “是否为管理岗”下拉框的清除按钮（×）默认可见。
7. 运行 `npx tsc --noEmit` 无类型错误。
